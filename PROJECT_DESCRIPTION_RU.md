## 3D Maze Game — подробное описание проекта

### 1. Назначение проекта

`3D Maze Game` — это учебный проект на Unity, в котором:
- **генерируется трёхмерный лабиринт** на основе заранее подготовленного рисунка/JSON‑файла;
- **шар (игрок)** двигается по уровню (через силу на `Rigidbody` или наклон платформы);
- **собирается статистика движения** (дистанция, скорость, количество столкновений) и сохраняется в CSV для дальнейшего анализа;
- **поддерживается управление от внешнего IMU‑датчика** через последовательный порт (опционально).

Проект развивает навыки работы:
- с 3D‑геометрией и генерацией уровня «на лету»;
- с физикой Unity (`Rigidbody`, `BoxCollider`);
- с UI (`TextMeshProUGUI`, кнопки, слайдеры);
- с файловой системой (`JSON`, `CSV`) и последовательным портом.

### 2. Общая архитектура

- **`Assets/Scenes`**
  - `Menu.unity` (предположительно) — главное меню.
  - `Game.unity` — основная игровая сцена с доской, шаром и уровнем.
  - Дополнительные тестовые сцены.
- **`Assets/Script`**
  - `MazeBuilder.cs` — генерация простого лабиринта из JSON в виде стен на плоскости.
  - `LevelManager.cs` — построение уровня на базе JSON‑описания мазка/линий (кубы, коллайдеры, сброс шара).
  - `Painter.cs` + `DrawnStroke.cs` + `Tool.cs` — система рисования уровня (кисть/линия/ластик) поверх текстуры.
  - `MenuController.cs` — переключение сцен (меню, игра, выход).
  - `StatisticsManager.cs` — сбор и сохранение статистики движения шара.
  - `SerialReader.cs` — чтение данных IMU с COM‑порта.
  - Вспомогательные скрипты (`CameraController`, `CameraSwitcher`, `LookAtTarget`, `Bezier` и др.).
- **`ProjectSettings`** — стандартные настройки Unity‑проекта.

### 3. Геймплей и управление

- Игрок управляет **шаром** на игровой доске/плоскости и должен:
  - пройти по лабиринту/нарисованному уровню;
  - избегать лишних столкновений со стенами/препятствиями;
  - дойти до целевой точки (реализация финиша может зависеть от конкретной сцены).
- Варианты управления:
  - **Клавиатура** — за счёт сил на `Rigidbody` по осям `Horizontal`/`Vertical` (закомментированная версия в `motion.cs`).
  - **IMU‑датчик** — ориентация считывается в `SerialReader`, а `motion.cs` (первая версия) использует данные наклона для добавления силы к шару.

### 4. Генерация уровня из JSON

#### 4.1. Формат данных

Основой уровня служит структура:

- **`DrawnStroke`** (`DrawnStroke.cs`):
  - `tool` (`Tool`) — тип инструмента (кисть или линия).
  - `color` (`Color`) — цвет мазка (может использоваться для визуальных эффектов).
  - `size` (`int`) — толщина мазка/линии.
  - `points` (`Vector2[]`) — набор точек в **нормализованных координатах** \([0, 1] × [0, 1]\), описывающих траекторию.
- **`StrokeListWrapper`** — список всех мазков уровня:
  - `List<DrawnStroke> strokes`.

JSON‑файл представляет собой сериализованный `StrokeListWrapper`.

#### 4.2. `MazeBuilder.cs`

- Создаёт **плоскость** (`Plane`) с заданным размером `planeSize` и материалом.
- Читает `jsonFile` (`TextAsset`) и для каждого штриха:
  - упрощает точки с помощью `SimplifyStroke`, чтобы убрать лишнюю детализацию;
  - по парам соседних точек строит **стенки** (кубы) через `CreateWallSegment`.
- Высота и толщина стен настраиваются параметрами `wallHeight` и `minWallThickness`.

#### 4.3. `LevelManager.cs`

- Инстанциирует `boardPrefab`, в котором:
  - `LevelContent` — контейнер, куда добавляются все элементы уровня;
  - `Ball` — объект шара.
- Считывает JSON из `Application.persistentDataPath` (например, `drawing.json`).
- Для каждого штриха:
  - если `Tool.Brush` — добавляет много маленьких кубиков (плотная заливка) и **объединяет меши** через `CombineInstance`, а для физики создаёт отдельные `BoxCollider` (уменьшенные через `colliderShrink`);
  - если `Tool.Line` — создаёт вытянутый куб между двумя точками (`BuildLineStroke`), вращая его вдоль линии.
- Координаты `Vector2` (\(0..1\)) преобразуются в мировые через `ConvertToWorld` с учётом `boardSize`.
- После постройки уровня вызывается `ResetBall` — сброс позиции шара и обнуление скоростей `Rigidbody`.

### 5. Редактор рисования (`Painter.cs`)

- Навешивается на объект с `Renderer` (обычно плоскость/квадрат).
- Создаёт `Texture2D` заданного размера и заполняет её цветом фона.
- Поддерживает три инструмента:
  - **Кисть (`Brush`)** — непрерывный мазок с округлой кистью;
  - **Линия (`Line`)** — рисование прямой между точкой нажатия и отпускания мыши;
  - **Ластик (`Eraser`)** — рисует фоновым цветом, стирая контент.
- Управление:
  - ЛКМ — рисование/указание начала и конца линии;
  - `B`/`L`/`E` — горячие клавиши выбора инструмента;
  - `Esc` — очистка текстуры;
  - UI‑кнопки/слайдер — выбор инструмента и размера кисти.
- Есть возможность сохранить текущее изображение в `paint_result.png` в `Assets`.

Отдельно от текстуры, этот же формат точек и инструментов используется для формирования JSON, который потом читают `MazeBuilder`/`LevelManager` (формирование JSON может быть реализовано в других скриптах/утилитах).

### 6. Статистика движения (`StatisticsManager.cs`)

- Реализует **синглтон** `StatisticsManager.Instance`.
- Назначается:
  - ссылки на UI‑тексты (`collisionsText`, `distanceText`, `speedText`);
  - объект игрока (`player` с `Rigidbody`).
- В `Update`:
  - считает **пройденную дистанцию** как сумму расстояний между кадрами;
  - берёт текущую **скорость** как `rb.linearVelocity.magnitude`;
  - каждые `recordInterval` секунд записывает:
    - позицию в список `trajectory`;
    - скорость в список `speeds`;
  - обновляет текстовые поля UI.
- Метод `AddCollision()` увеличивает счётчик столкновений и обновляет UI; его следует вызывать в `OnCollisionEnter` шара (`motion.cs`).
- Метод `SaveStatistics()`:
  - сохраняет CSV‑файл `BallStats.csv` в `Application.persistentDataPath`;
  - записывает таблицу `Time;X;Y;Z;Speed` для каждой точки траектории;
  - в конце дописывает итоговую дистанцию и количество столкновений.
- По умолчанию сохранение можно вызвать по клавише `F5`.

### 7. Подключение IMU‑датчика (`SerialReader.cs` и `motion.cs`)

- `SerialReader.cs`:
  - открывает последовательный порт (`COM8`, `115200` бод по умолчанию);
  - в отдельном потоке непрерывно читает данные;
  - ожидает строки формата: `Ax Ay Az Gx Gy Gz` (6 чисел через пробел);
  - парсит их и помещает в массив `imu[6]`, потокобезопасно (через `lock`).
- `motion.cs` (первая версия, сейчас закомментирована):
  - получает ссылку на `SerialReader`;
  - в `FixedUpdate` берёт данные наклона и через `AddForce` смещает шар.
- Альтернативная (вторая) версия `motion.cs` использует классические оси ввода `Horizontal`/`Vertical` от клавиатуры.

### 8. Запуск проекта

1. **Открыть проект в Unity.**
2. Убедиться, что основная версия проекта запускается со сцены `Menu` или `Game` (через `Build Settings` → `Scenes In Build`).
3. Проверить, что в сцене:
   - на объекте с лабиринтом/доской присутствуют `MazeBuilder` или `LevelManager` с корректно привязанным JSON/именем файла;
   - у `StatisticsManager` назначены ссылки на `player` и элементы UI;
   - для использования IMU настроен правильный `portName` в `SerialReader`.
4. Запустить проигрывание сцены (`Play`) и протестировать:
   - перемещение шара;
   - корректную генерацию уровня;
   - обновление статистики и сохранение CSV (клавиша `F5`).

### 9. Требования и примечания

- **Среда**: Unity (рекомендуется версия 2021.x или новее).
- **Язык скриптов**: C#.
- **Платформы**: основной таргет — настольные ОС (Windows), но проект можно адаптировать под другие платформы.
- Для работы с IMU требуется:
  - корректно настроенный COM‑порт;
  - внешний контроллер, отправляющий строки в ожидаемом формате.

### 10. Подробно: что сделано в проекте и как это реализовано

Ниже — связное описание для пояснительной записки: перечислены реализованные части, их назначение и принцип работы.

#### 10.1. Общая идея

Реализована **3D‑игра с шаром на доске**, где препятствия (лабиринт) можно **задать данными из JSON**, полученными из **нарисованного уровня** (кисть/линии). Дополнительно предусмотрены **учёт движения** (дистанция, скорость, столкновения, экспорт в CSV) и **управление через внешний IMU** по **последовательному порту** (Windows, `System.IO.Ports`).

#### 10.2. Генерация уровня — что сделано

**Два подхода в коде:**

1. **`MazeBuilder.cs`** — при старте сцены создаётся плоскость‑пол, из **JSON, вложенного в проект как `TextAsset`**, строятся **стены**: каждый штрих превращается в цепочку отрезков, по каждому отрезку создаётся вытянутый куб с кинематическим `Rigidbody`. Точки штриха **упрощаются** (отбрасываются слишком близкие), чтобы не плодить лишнюю геометрию. Так можно быстро получить «лабиринт‑стены» из одного файла без рантайм‑записи на диск.

2. **`LevelManager.cs`** — ориентирован на **игровую доску‑префаб** с дочерними объектами `LevelContent` (куда кладутся кубы уровня) и `Ball`. Уровень читается из **`Application.persistentDataPath`** (например, `drawing.json`) — то есть файл может быть **записан приложением** или скопирован туда вручную. Штрихи **кистью** превращаются в набор позиций кубиков: визуально они **объединяются в один меш** (`CombineMeshes`) для производительности, а **коллайдеры** создаются отдельными уменьшенными `BoxCollider` под каждую «ячейку», чтобы физика была стабильнее. Штрихи **линией** — это один вытянутый куб между двумя точками. После загрузки **шар сбрасывается** в стартовую позицию с обнулением скоростей.

**Формат данных** унифицирован: классы `DrawnStroke` и `StrokeListWrapper` описывают список штрихов с инструментом, цветом, размером и массивом точек в нормализованных координатах \([0,1]\) по плоскости доски.

#### 10.3. Редактор рисования — что сделано

**`Painter.cs`** — на объекте с `Renderer` создаётся **растровая текстура**; рисование идёт **лучом из камеры** в поверхность, координаты `textureCoord` переводятся в пиксели. Реализованы **кисть** (непрерывные круги по траектории), **прямая линия** между нажатием и отпусканием мыши, **ластик** (закраска цветом фона). Есть **очистка по Esc**, горячие клавиши выбора инструмента, привязка к UI (кнопки, слайдер размера), **сохранение PNG** в папку `Assets`. Это даёт «холст» для проектирования уровня визуально; экспорт в JSON для `LevelManager`/`MazeBuilder` может выполняться отдельным кодом или внешним инструментом — в проекте зафиксирована **структура данных** и **чтение** JSON.

#### 10.4. Физика шара и меню — что сделано

- Шар двигается за счёт **`Rigidbody.AddForce`** — либо от **осей ввода** (клавиатура), либо в задуманном варианте — от **данных IMU** (см. ниже).
- **`OnCollisionEnter`** на скрипте движения вызывает **`StatisticsManager.Instance.AddCollision()`** для учёта ударов.
- **`MenuController.cs`** — загрузка сцены по имени, выход из приложения, возврат в меню — простая навигация между экранами.

#### 10.5. Статистика — что сделано

**`StatisticsManager.cs`** — паттерн **singleton** (один экземпляр в сцене). В **каждом кадре** накапливается **пройденный путь** (сумма расстояний между позициями), на экран выводятся **дистанция** и **модуль скорости**. С заданным шагом по времени (`recordInterval`) в списки записываются **точки траектории** и **скорости** — для последующего анализа. По нажатию **F5** (в коде) вызывается сохранение **`BallStats.csv`** в `persistentDataPath`: колонки время, координаты, скорость; в конце файла — **итоговая дистанция** и **число столкновений**. Это позволяет приложить к записке графики траектории или обработать данные в Excel/Python.

#### 10.6. Работа с IMU — что сделано и как устроено

**Назначение:** подключить **реальный инерциальный модуль** (или микроконтроллер с IMU), который передаёт измерения по **UART/USB как COM‑порт** в Unity на ПК.

**Реализация в `SerialReader.cs`:**

- Используется **`System.IO.Ports.SerialPort`**: в инспекторе задаются **имя порта** (например, `COM8`) и **скорость** (по умолчанию **115200** бод).
- При старте выполняется **открытие порта**; при ошибке сообщение пишется в консоль, игра не «падает», но данных не будет.
- Чтение организовано **в отдельном потоке** (`Thread`), чтобы не блокировать главный поток Unity. В цикле читаются фрагменты текста, они **накопляются в буфере** до символа перевода строки — так обрабатываются **неполные строки** при пакетной передаче.
- **Формат одной строки от устройства:** шесть чисел через пробел, в порядке:
  - **Ax, Ay, Az** — компоненты ускорения (или линейного ускорения в единицах, которые шлёт прошивка);
  - **Gx, Gy, Gz** — компоненты угловой скорости (гироскоп), в тех же единицах, что задаёт прошивка.
- Строка **разбирается**, шесть значений приводятся к `float` и **атомарно** (через `lock`) записываются в массив **`imu[6]`** для чтения из других скриптов.
- Публичный метод **`GetIMU()`** возвращает **копию** массива, чтобы избежать гонок при изменении данных в фоне.
- При уничтожении объекта поток **корректно останавливается**, порт **закрывается**.

**Связь с движением шара (`motion.cs` — вариант с IMU):**

- В репозитории **активный код движения закомментирован**; в нём задумано следующее:
  - в `Awake` берётся **`Rigidbody`** и через **`FindObjectOfType`** находится **`SerialReader`**;
  - в **`FixedUpdate`** на шар должна добавляться сила **`(x * speed, 0, y * speed)`**, где **x и y** — компоненты «наклона**, полученные из последовательного порта (в комментарии вызывается **`GetTilt()`** — в текущем `SerialReader` объявлен **`GetIMU()`**, а не `GetTilt()`; для полной сборки варианта с IMU нужно либо **добавить в `SerialReader` метод**, который из `imu[]` вычисляет двумерный наклон (например, из проекций ускорения силы тяжести), либо **использовать `GetIMU()`** прямо в `motion` и вручную сопоставить оси датчика осям сцены).
- Во втором закомментированном блоке того же файла показан **альтернативный режим без железа**: **`Input.GetAxis("Horizontal")` / `Vertical`** и та же схема **`AddForce`** — удобно для отладки без COM‑порта.

**Что требуется на стороне железа/прошивки:**

- Устройство должно **непрерывно** слать строки вида:  
  `Ax Ay Az Gx Gy Gz`  
  (разделитель — пробел, конец строки — `\n`), с частотой и бодом, согласованными с настройками порта в Unity.
- Для управления наклоном доски обычно используют **акселерометр** (гравитация даёт направление «вниз») или **комбинированную фильтрацию** акселерометра и гироскопа; в проекте **заложен сырой поток данных**, а конкретная логика «тилта» может быть доработана под вашу модель.

**Итог по IMU:** реализованы **приём данных по COM‑порту в фоновом потоке**, **разбор строк**, **потокобезопасное хранение** и **интеграция с движением шара** (задумана в закомментированном `motion.cs`); для сдачи проекта важно явно описать: формат пакета, параметры порта, назначение шести полей и то, как они переводятся в силу на `Rigidbody`.
