## Описание основных алгоритмов проекта

В этом документе описаны ключевые алгоритмы проекта простыми словами, без привязки к синтаксису C#. Каждый раздел можно использовать как основу для блок‑схемы.

---

### 1. Алгоритм построения уровня (класс управления уровнем)

**Смысл алгоритма**  
Игра должна создать игровую доску и расставить на ней препятствия по данным из JSON‑файла. После этого шарик возвращается в стартовую позицию.

**Общий ход работы при запуске сцены**
1. Сначала вычисляется реальный размер игровой доски в мире на основе масштаба плоскости (переводится из условных единиц Unity в метры по осям X и Z).
2. Создаётся экземпляр готового префаба доски, который уже содержит всё нужное оформление и вложенные объекты.
3. Внутри созданной доски отыскивается специальный контейнер, куда будут добавляться все элементы уровня (стены, кубики и т.п.).
4. Внутри той же доски находится объект шарика, которым управляет игрок.
5. Дальше по имени загружается JSON‑файл с описанием нарисованного уровня (штрихи и линии).
6. Если файла нет, выполнение останавливается с сообщением об ошибке. Если файл есть — строка с JSON‑данными читается полностью.
7. Строка интерпретируется как структура «список штрихов», где каждый штрих хранит:
   - каким инструментом рисовали (кисть или линия);
   - толщину;
   - набор точек в относительных координатах от 0 до 1.
8. На основе этого списка запускается процесс построения уровня:
   - штрихи, нарисованные «кистью», превращаются в множество отдельных кубиков‑плиток;
   - штрихи‑линии превращаются в вытянутые прямоугольные блоки‑перегородки.
9. После того как все объекты уровня созданы, шарик возвращается в исходную позицию и его скорости обнуляются, чтобы он начинал движение из одного и того же места.

**Построение области, нарисованной кистью**
1. Для каждого штриха‑«кисти» перебираются все точки, по которым проходил курсор.
2. Чтобы не создавать дубликаты, точки запоминаются во множестве, и повторяющиеся позиции пропускаются.
3. Каждая точка задаётся в относительных координатах (от 0 до 1 по ширине и высоте поля). Эти координаты переводятся в реальные координаты мира, умножением на физический размер доски.
4. Для визуальной части уровня планируется создать много одинаковых кубиков и затем объединить их в один большой меш (для оптимизации). Для этого:
   - от исходного кубика‑образца берётся его форма;
   - для каждой точки рассчитывается матрица преобразования: куда этот куб надо перенести и в каком масштабе.
5. Эти параметры добавляются в специальный список для последующего объединения.
6. Отдельно для физики (столкновений) под каждую такую точку создаётся невидимый объект только с коллайдером:
   - он ставится в ту же позицию;
   - его размер немного уменьшается относительно видимого кубика, чтобы физика чувствовалась корректнее и шар не «цеплялся» за края.
7. После обработки всех точек из всех штрихов список с описанием кубиков объединяется в единый 3D‑объект:
   - создаётся пустой объект;
   - к нему прикрепляется один общий меш и общий материал;
   - все мелкие кубики сливаются в одну сетку.

**Построение линии‑преграды**
1. Для штриха‑линии используются только первые две точки — начало и конец сегмента.
2. Они переводятся из относительных координат в реальные координаты игрового поля.
3. Вычисляется середина между началом и концом — в ней будет находиться центр будущего блока.
4. Вычисляется вектор от начала к концу и его длина — это определяет, как повернуть и насколько вытянуть блок.
5. Создаётся новый кубик по центру отрезка.
6. Кубик поворачивается так, чтобы он «смотрел» вдоль отрезка (то есть был выровнен по направлению линии).
7. Размер кубика по длине растягивается ровно до длины отрезка, а по высоте задаётся настроенным параметром высоты преграды.
8. Добавляется или обновляется коллайдер так, чтобы он покрывал всю новую форму.

**Очистка уровня и сброс шарика**
1. При загрузке нового уровня все дочерние объекты в контейнере уровня удаляются, чтобы не накладывать новый лабиринт на старый.
2. Для шарика находится компонент физики.
3. Его линейная и угловая скорость принудительно обнуляются.
4. Позиция шарика возвращается в фиксированную стартовую точку над поверхностью доски.

### 2. Алгоритм работы редактора рисования (панель с кистью, линией и ластиком)

**Смысл алгоритма**  
Игрок или пользователь должен иметь возможность рисовать уровень прямо по поверхности: свободной кистью, прямыми линиями или стирать части рисунка. Всё рисование ведётся на текстуре, натянутой на объект в сцене.

**Подготовка текстуры и интерфейса**
1. При запуске редактора из объекта берётся его визуальный компонент, который отвечает за отображение материала.
2. Создаётся новая пустая текстура заданного размера (по ширине и высоте в пикселях).
3. Эта текстура заполняется однотонным цветом фона — так получается «чистый лист».
4. Текстура устанавливается как основное изображение материала на объекте, чтобы пользователь видел, что он рисует.
5. Если к скрипту подключены кнопки и слайдеры интерфейса:
   - каждая кнопка привязывается к изменению активного инструмента (кисть, линия, ластик);
   - слайдер отвечает за размер кисти (толщину);
   - при изменении слайдера обновляется подпись с текущим размером;
   - отдельная кнопка может быть назначена для сохранения изображения в файл.

**Реакция на нажатие и движение мыши**
1. Когда пользователь нажимает левую кнопку мыши:
   - запоминается факт, что кнопка сейчас зажата;
   - из камеры в точку курсора выпускается луч, чтобы узнать, попал ли он в поверхность для рисования;
   - если попадание есть, берутся координаты точки на текстуре.
2. Далее поведение зависит от выбранного инструмента:
   - если активен режим линии, текущая точка запоминается как начало будущей линии;
   - если активна кисть или ластик, точка сразу переводится из долей текстуры в целые пиксели, в этой области рисуется круг соответствующего цвета (чёрный для кисти, цвет фона для ластика), и запоминается последняя точка, откуда начался штрих.
3. Пока левая кнопка мыши удерживается и курсор двигается:
   - для кисти и ластика:
     1. на каждом кадре снова проверяется пересечение луча с плоскостью;
     2. каждое новое попадание превращается в координату пикселя;
     3. между предыдущей точкой и новой точкой рисуется линия из серии кругов, чтобы штрих выглядел гладко;
     4. новая точка становится «последней» для следующего шага.
   - для линии на этом этапе ничего не рисуется, линия будет проведена только после отпускания кнопки.
4. Когда пользователь отпускает левую кнопку мыши:
   - снова проверяется попадание луча в поверхность;
   - если активен режим линии:
     1. берётся вторая точка (место отпускания кнопки);
     2. начало и конец переводятся в пиксели;
     3. по этим двум точкам рисуется отрезок в виде цепочки кругов;
   - если активна кисть или ластик:
     1. финальная точка штриха дополнительно прорисовывается, чтобы не было пробелов.
   - после завершения штриха делается применение изменений текстуры, чтобы результат был виден на экране.
5. В конце отпускания кнопки состояние «кнопка зажата» сбрасывается, а информация о последней точке обнуляется.

**Дополнительные действия пользователя**
1. По нажатию клавиши Escape вся текстура заполняется цветом фона, то есть холст полностью очищается.
2. По горячим клавишам можно сменить активный инструмент:
   - одна клавиша включает кисть;
   - другая — инструмент рисования линии;
   - третья — ластик.
3. При нажатии специальной кнопки «сохранить» текущее изображение кодируется в PNG и записывается в файл на диск.

**Перевод координат и рисование на уровне пикселей**
1. Все координаты, полученные от луча, изначально находятся в диапазоне от 0 до 1 как доля от ширины и высоты текстуры.
2. Для реального пикселя они умножаются на размер текстуры и округляются до ближайшего целого.
3. Рисование ведётся кругами:
   - выбирается квадратная область вокруг центра;
   - для каждого пикселя в этой области проверяется, попадает ли он внутрь окружности заданного радиуса;
   - если попадает, цвет пикселя заменяется на цвет кисти или фон.
4. Чтобы линия не состояла из отдельных точек при быстром движении мыши, между двумя точками штриха строится серия промежуточных кругов, равномерно расположенных по отрезку.

### 3. Алгоритм сбора и сохранения статистики движения шара

**Смысл алгоритма**  
Во время игры нужно собирать информацию о том, как движется шарик: сколько он прошёл, с какой скоростью и сколько раз ударился. Эти данные потом сохраняются в таблицу для анализа.

**Подготовка к измерениям**
1. При создании объекта статистики проверяется, что уже нет другого такого же объекта в сцене. Если есть — дубликат удаляется, а один экземпляр сохраняется как «единственный».
2. Объекту статистики заранее в инспекторе назначают:
   - ссылки на текстовые поля интерфейса, где будут показываться расстояние, скорость и число столкновений;
   - ссылку на сам шарик‑игрока.
3. Во время инициализации с шарика берётся компонент физики.
4. Запоминается начальная позиция шарика.
5. В списки для записи траектории заносится первая точка (стартовая) и начальная нулевая скорость.

**Непрерывный пересчёт статистики**
1. На каждом кадре выполняются одни и те же шаги, пока объект активен:
   - если по какой‑то причине не удалось получить компонент физики, пересчёты пропускаются.
2. Вычисление пройденного расстояния:
   - берётся текущая позиция шарика;
   - считается расстояние между текущей и предыдущей позицией;
   - это расстояние добавляется к общему счётчику пройденного пути;
   - текущая позиция сохраняется как «предыдущая» для следующего кадра.
3. Обновление показаний на экране:
   - если текст для расстояния задан, в нём обновляется число метров с округлением до двух знаков;
   - если текст для скорости задан, в нём показывается текущая скорость шарика, полученная из физического компонента, также с округлением.
4. Периодическая запись траектории:
   - в специальном таймере накапливается время;
   - как только оно превышает заданный интервал (например, десятые доли секунды), текущая позиция и скорость добавляются в списки траектории и скоростей;
   - таймер обнуляется, и всё повторяется.
5. При нажатии заданной горячей клавиши (в проекте используется F5) запускается сохранение всей накопленной статистики в файл.

**Учёт столкновений**
1. В скриптах, отвечающих за движение шарика, при каждом столкновении вызывается метод, который увеличивает счётчик ударов.
2. После увеличения счётчика, если в интерфейсе есть соответствующее текстовое поле, в нём сразу отображается новое значение.

**Сохранение статистики в файл**
1. При попытке сохранения сначала проверяется, что траектория не пуста. Если данных нет, выводится предупреждение, и процесс прекращается.
2. Формируется путь к файлу внутри служебной папки приложения (чтобы он был доступен и на рабочем столе, и при сборке).
3. Открывается текстовый файл для записи.
4. В первую строку записывается заголовок таблицы, где обозначены:
   - время;
   - координаты по осям X, Y, Z;
   - скорость.
5. Вводится переменная времени, которая по умолчанию равна нулю.
6. Затем для каждой записанной точки траектории по очереди:
   - берётся сохранённая позиция и соответствующая ей скорость;
   - формируется строка с этими значениями и текущим временем;
   - время увеличивается на шаг, равный интервалу записи траектории.
7. После всех строк оставляется пустая строка для наглядности.
8. В конец файла добавляются две итоговые строки:
   - суммарное пройденное расстояние;
   - общее количество столкновений.
9. Файл закрывается, и в консоль выводится сообщение об успешном сохранении либо об ошибке, если она возникла.

### 4. Алгоритм чтения данных с IMU через последовательный порт

**Смысл алгоритма**  
Внешний датчик (например, акселерометр и гироскоп) по последовательному порту постоянно отправляет строки с шестью числами. Скрипт должен открывать порт, непрерывно читать эти строки в отдельном потоке, разбирать числа и хранить их в удобном виде для других частей программы.

**Настройка и открытие порта**
1. При запуске создаётся объект, описывающий подключение к порту:
   - указываются имя порта (например, COM8) и скорость передачи (количество бит в секунду).
2. Задаётся небольшое время ожидания чтения, чтобы программа не зависала, если данных нет.
3. Делается попытка открыть порт:
   - если открыть удалось, в переменной состояния отмечается, что чтение активно;
   - создаётся новый поток, предназначенный только для считывания данных;
   - этот поток запускается и начинает выполнять функцию чтения в цикле;
   - в журнал записывается сообщение об успешном открытии порта.
   - если открыть порт не удалось (например, его не существует или он занят), генерируется сообщение об ошибке, а чтение не запускается.

**Непрерывный цикл чтения данных**
1. В отдельном потоке создаётся строка‑буфер, куда будут складываться приходящие куски текста.
2. Пока флаг «работаем» не выключен:
   - делается попытка прочитать всё, что пришло в порт на данный момент;
   - если пришли новые символы, они добавляются в конец буфера;
   - в буфере ищутся символы перевода строки — каждый такой символ обозначает конец одного сообщения;
   - до перевода строки вырезается одна строка, обрезается от служебных символов по краям и передаётся на разбор;
   - остаток после последнего перевода строки остаётся в буфере, чтобы дождаться продолжения в следующем чтении.
3. Если при чтении возникает ошибка (например, порт внезапно закрылся или временно недоступен), ошибка перехватывается, и в журнал пишется предупреждение, но поток продолжает попытки чтения.
4. Между итерациями делается небольшая задержка, чтобы цикл не загружал процессор впустую.

**Разбор строки от датчика**
1. Ожидается, что каждое сообщение — это одна строка с шестью числами, разделёнными пробелами:
   - три числа для ускорения по осям X, Y, Z;
   - три числа для угловой скорости по этим же осям.
2. При разборе строка разделяется на части по пробелу.
3. Если число частей не равно шести, строка считается некорректной и игнорируется, в журнал при этом может быть выведено предупреждение.
4. Если частей шесть, каждая из них по очереди переводится из текстового представления в вещественное число.
5. Значения сохраняются в фиксированный массив из шести элементов.
6. Запись в массив закрывается на короткую блокировку, чтобы другие потоки не читали значения одновременно с их обновлением.
7. Если при переводе строки к числам возникает ошибка (например, в строке есть буквы), генерируется предупреждение, и текущая строка пропускается.

**Предоставление последних измерений другим скриптам**
1. Для других частей программы предусмотрен метод, который возвращает последние считанные данные.
2. При вызове этого метода массив с шестью числами копируется и только копия отдаётся вызывающему коду.
3. Это делается для того, чтобы защитить «рабочий» массив от случайных изменений.

**Корректное завершение работы**
1. Когда объект, отвечающий за работу с портом, уничтожается (например, при смене сцены), флаг работы чтения сбрасывается.
2. Поток чтения, если он существует, дожидается завершения цикла и корректно закрывается.
3. Если порт всё ещё открыт, он закрывается.
4. В журнал записывается сообщение о том, что порт был закрыт.

### 5. Алгоритм управления шариком на основе IMU (вариант с датчиком)

**Смысл алгоритма**  
В этом варианте шарик двигается не от клавиш, а от наклона внешнего датчика. Данные о наклоне считываются через последовательный порт, а затем преобразуются в силы, приложенные к шару в физическом мире Unity.

**Подготовка объекта шарика**
1. При создании шарика к нему уже должен быть прикреплён компонент физики, который позволяет на него действовать силами.
2. В начале работы скрипта, отвечающего за движение:
   - находится и запоминается физический компонент;
   - по всей сцене ищется объект, который читает данные с последовательного порта (описанный в предыдущем разделе), и сохраняется ссылка на него.

**Преобразование данных датчика в движение**
1. На каждом фиксированном шаге физического обновления (специальный цикл Unity для работы с физикой) выполняются следующие действия:
   - если ссылки на объект чтения данных нет (например, он не инициализировался), обновление движения пропускается;
   - если ссылка есть, у него запрашиваются последние измерения.
2. Из набора чисел, пришедших с датчика, выбираются компоненты, отвечающие за наклон в двух плоскостях (например, по осям X и Y).
3. Эти значения рассматриваются как «команды управления»:
   - одно число задаёт опрокидывание доски вперёд‑назад;
   - второе — влево‑вправо.
4. Для шарика формируется вектор силы:
   - горизонтальная составляющая пропорциональна наклону влево‑вправо;
   - глубинная составляющая пропорциональна наклону вперёд‑назад;
   - вертикальная составляющая равна нулю, чтобы шар не подбрасывало вверх.
5. Весь вектор масштабируется общим коэффициентом чувствительности, который задаёт, насколько сильно шар будет реагировать на наклон датчика.
6. Получившийся вектор силы прикладывается к шару через физический движок. В результате шар начинает катиться в направлении, соответствующем наклону реального устройства.

**Реакция на столкновения**
1. На шарике настроен обработчик столкновений.
2. Каждый раз, когда шарик ударяется о какое‑то препятствие, вызывается специальная функция у объекта, который ведёт статистику.
3. Эта функция увеличивает счётчик столкновений и обновляет надпись на экране, чтобы игрок видел, сколько раз шар уже ударился.

**Итог**  
Вся цепочка выглядит так: внешний датчик → строки с числами по порту → внутренний буфер данных → преобразование наклона в силы → перемещение шарика → учёт столкновений и статистики. На основе этого описания удобно рисовать блок‑схему, начиная с «инициализация компонентов» и заканчивая «обновление положения и статистики в каждом кадре».
